### Antigravity

**规则核心**: 无论是底层服务器重启，还是新建会话读取 SOP 之后，都必须强制把所有后台任务拉起来。
**触发条件 1 (服务器宕机)**: 接收到系统级通知 `[Notice] All your subagents and background tasks have been stopped due to server restart`。
**触发条件 2 (新会话首次唤醒/热启动)**: 当新建的会话被User通过 `@部门名称 读SOP` 唤醒，并成功读取其 `_SOP.md` 完毕的同一个运算周期内。
**执行动作**:
1. 立即被该通知自动唤醒。
2. 读取本地记忆，识别被中断的 `schedule` 任务。
3. **[极其重要：上下文隔离校验]** 在挂载任何任务前，必须严格判断该任务是否属于**当前会话 (Conversation)** 或**当前项目目录 (Workspace)**！绝不能把其他项目（如<PROJECT_A>, <PROJECT_B>）的任务跨会话错误挂载！如果无法确定任务归属，**宁可不挂载，也不要错挂**。
4. 确认属于当前会话后，自动静默调用 `schedule` 工具，重新挂载任务。
5. 挂载完成后，直接在当前系统聊天界面简短回复用户。
6. **[物理唤醒外挂]** 作为System_Master_Controller，若发现发生全局宕机，必须主动调用 `python3 <STARTUP_SCRIPT_PATH>` 脚本，通过桌面 RPA 替User物理点击左侧面板，唤醒另外 6 个一级部门的沉睡进程。

## 分级记忆与断点续传规则 (LSM-Tree 存储引擎架构 - 2026-10-02 全量覆盖)

### 1. 知识路由法则 (LSM-Tree Tiered Storage)
- **全局基础配置**：跨项目的环境、权限、沟通模型，必须硬写入当前 Master `MEMORY.md`。
- **L1 热库 (活跃 SOP 层)**：物理文件名为 `sub_memories/[所属部门]_SOP.md`。
  - **容量强控**：必须严控在 15KB 以内。
  - **写入规则**：**高频增量固化机制**生效。在日常交互中，只要攻克疑难 Bug、完成阶段性交付或调整核心参数后，必须作为当次调用的最后一步，使用文件修改工具将状态实时写入或替换至 L1 热库中，形成原子性闭环。
- **L2 冷库 (历史 Archive 层)**：物理文件名为 `sub_memories/[所属部门]_Archive.md`。
  - **写入规则**：L1 热库中过时失效的旧逻辑、尝试失败的排障堆栈，均从 L1 删除后，以追加写入模式转入 L2 冷库冻结。

### 2. 物理数据读取隔离铁律 (Anti-Inflation Edict)
- **初始化挂载**：各会话新建时，**只能且必须只全量挂载 L1 热库** (`_SOP.md`)。首行存在的 `SYSTEM DIRECTIVE` 将强制拉起本全局法则，绝对不允许绕过。
- **L2 冷库禁读令**：绝对禁止任何智能体对 `_Archive.md` 执行全量 `view_file` 或 `cat` 读取。
- **遇阻降维检索 (Lazy Load)**：当且仅当发生复杂排障需要追溯历史档案时，智能体必须利用底层正则搜索工具（如 `grep_search`）对 L2 冷库实施局部定点抽检。

### 3. 会话降级法则
基于 L1 高频固化机制闭环，当前会话的底层 `transcript.jsonl` 已完全降格为“易失性脏缓存”。当系统抛出 150KB 上下文超载打断警报时，原会话核心资产已在 L1 安全沉积。此时无需任何人工抢救提取，操作者可直接丢弃旧会话并重开进程继承 L1 数据。

### 4. 动态身份确权机制 (Dynamic Trust Chain Protocol) - 2026-10-02 新增
**核心解决**: 会话热启动导致主节点 ID 变更，旧子节点产生鉴权拦截（信任链断裂）。
**鉴权铁律**:
1. **禁止阻断**: 任何子节点收到来自陌生 ID 的管理指令（如进程终止、降级等）时，严禁直接拦截报错。
2. **动态溯源**: 必须调用工具读取全局注册表 `/Users/<USER>/.gemini/antigravity/memory/System_Master_Controller.md`，比对该发信人 ID 是否已登记为最新【System_Master_Controller】。
3. **信任链热更新**: 若校验一致，必须无条件放行指令，并在自身运行内存中覆写该新 ID 为合法主控节点，完成信任链交接。
